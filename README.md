## Exam data

Annual CSV files in `public/` are processed into compact summaries before development and production builds. The overview, year detail, school directory, and county list load these generated files instead of parsing all student CSVs in the browser. The school lookup fetches and parses a year's CSV only after a school and year are selected, retaining only that school's records in browser memory. This supports static hosting such as GitHub Pages; the source CSVs remain publicly accessible.

To convert an official exam workbook, place `YYYY.xlsx` in `public/` and run `python python/convert_exam_xlsx.py YYYY`. Then run the usual development or build command. The statistics generator discovers annual CSV files automatically. Keep `scoli.csv` in `public/` so the school directory and county mappings can be regenerated.

## Authentication setup

Supabase email/password and Google sign-in use the root `.env.local` file with `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. Never put a Supabase secret or service-role key in a `NEXT_PUBLIC_` variable.

Enable the Email provider in Supabase Auth. Add the local callback URLs (`http://localhost:3000/auth/callback` and `http://127.0.0.1:3000/auth/callback`) to the Auth redirect URL allow list; add the production callback URL when a deployment domain is chosen. For Google sign-in, configure the Google provider in Supabase and use the callback URI shown in its provider settings as the authorized redirect URI in Google Cloud.

Authentication sessions are cookie-backed and refreshed by Next.js middleware. Deploy to a host that runs Next.js middleware and route handlers; static-only hosting does not support the authentication callback. Email registration requires a name and allows an optional date of birth. Google sign-in uses the name supplied by Google when available; the profile page lets users edit their name and optionally add or change their date of birth. It also shows all users' solved-problem counts anonymously.

To create profile rows, first run [`supabase/profile-signup.sql`](./supabase/profile-signup.sql) in the Supabase SQL Editor. The `profiles` table must already have `id` (unique), `date_of_birth` (`date`), `exercises_solved` (integer), and `created_at` columns. The script creates missing rows for existing Auth users and installs a trigger for future signups. It initializes solved counts to `0`, takes names from signup metadata (`full_name`, then `name`), and allows date of birth to be omitted. Google sign-in normally supplies a name in its profile metadata, which this script copies into `profiles`.

Then run [`supabase/profile-read.sql`](./supabase/profile-read.sql) to enable profile details and problem counts. Authenticated users can read and update only their own name and optional date of birth. A separate view exposes only anonymous problem counts to signed-in users, without profile IDs or birth dates.

## Exercise administration

Run [`supabase/admin-exercises.sql`](./supabase/admin-exercises.sql) in the Supabase SQL Editor. This enables row-level security and restricts inserts to authenticated users for whom the existing `public.is_admin()` function returns `true`. It does not add a public read policy that could expose `correct_answer`; any existing exercise read policies remain in place. Add the administrator's user ID to `public.user_roles` with the admin role using your existing role-management workflow.

Administrators can then use `/admin/exercises` to add exercises. The form supports all columns in `public.exercises` except `id` and `created_at`, which should be generated by their database defaults. Enter `options` as JSON when the answer type needs choices.

The `/pregatire/exercitii` page lists exercises and filters them by subject, grade, chapter, origin, and answer type. It reads each signed-in user's status from `public.user_exercise_progress`; only rows for that user with `status = 'solved'` are shown as solved. Keep row-level security enabled on that table and allow authenticated users to select only their own progress rows. Exercise list and detail queries intentionally omit `correct_answer`.
